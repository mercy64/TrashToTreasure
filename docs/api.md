# API Documentation (summary)

This file contains a concise machine-readable summary of the key API endpoints introduced for the frontend to consume.

## Authentication
- POST /api/accounts/register/ - Register
- POST /api/accounts/login/ - Login (returns JWT access/refresh)

## Listings
- GET /api/waste/listings/
  - Query params: type, location, min_quantity
- POST /api/waste/listings/create/ (authenticated)
  - Body: { title, description, type, quantity, unit, location, latitude, longitude, price_per_unit }
- POST /api/waste/listings/<id>/claim/ (authenticated)
- POST /api/waste/listings/<id>/unclaim/ (authenticated)
- POST /api/waste/listings/<id>/unassign/ (authenticated: assigned user or admin)

## Prices
- GET /api/waste/prices/ - list active
- POST /api/waste/prices/ - estimate total; body: { type, quantity, unit }
- POST/PUT/DELETE /api/waste/prices/manage/ (admin) - CRUD

## Routes
- POST /api/waste/routes/assign/ (delivery or admin)
  - Body: { collector_id, max_count }
  - Returns: { id, collector, ordered_listing_ids, created_at }

## Notifications
- In-app notifications are created automatically when a listing is claimed/assigned/unassigned. Use `/api/accounts/profile/` to get user info and a notification endpoint can be added similarly.

## Notes for Frontend
- Attach `Authorization: Bearer <access_token>` for authenticated endpoints.
- Real-time updates: consider polling `/api/accounts/notifications/` or integrate WebSocket consumer (channels) for live updates (not implemented in this release; see signals.py for sending notifications).

## OpenAPI/Swagger
- A formal OpenAPI JSON can be generated by Django REST Framework's schema generators; for now use this summary to wire the frontend.
